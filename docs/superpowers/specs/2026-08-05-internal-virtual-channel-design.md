# 内部虚拟通道设计

## 目标

移除依赖 com0com 和 Windows 内核驱动的系统虚拟 COM 功能，增加仅供本机多个软件实例互通使用的“内部虚拟通道”。该通道不注册 COM 端口、不修改设备管理器、不需要管理员权限，也不开放局域网访问。

## 用户体验

- 协议下拉框增加“内部虚拟通道”，与 Modbus RTU、Modbus ASCII、Modbus TCP 并列。
- 选择内部虚拟通道后，隐藏 COM 端口、刷新、虚拟串口按钮、波特率、数据位、校验位、停止位和流控。
- 显示“通道名称”输入框，默认值为空或上次使用值，并限制为安全的短文本。
- 主站点击“加入通道”，从站点击“创建通道”。同名通道用于连接两个软件实例。
- 连接成功后，按钮显示“关闭通道”，状态徽标显示“内部通道 · 主站/从站 · 已连接”。
- 通道不存在、名称无效、对端未启动或连接断开时，在状态栏和日志中给出可操作的中文提示。

## 架构

内部通道使用本机 TCP 回环地址 `127.0.0.1` 承载 Modbus RTU 帧。通道名通过稳定的本地映射转换为回环端口，映射范围避开常用端口并保证同一名称在两个实例中得到相同结果。

- 从站创建 `QTcpServer`，只监听 `127.0.0.1`。
- 主站使用 `QTcpSocket` 连接同一回环端口。
- 连接建立后，沿用现有 RTU 帧读写、帧间隔、超时、从站处理和解析流程。
- 内部通道不复用 `QSerialPort`，但所有上层 Modbus 业务保持不变。
- 一个通道只允许一个主站和一个从站；重复创建或加入应返回明确错误。

## 生命周期与错误处理

- 切换协议或关闭窗口前，主动断开内部 socket 并关闭监听器。
- 主站连接超时、从站监听失败、通道名映射冲突和对端断开都必须清空缓冲区并恢复“未连接”状态。
- 不执行 PowerShell 提权，不查找 `setupc.exe`，不调用 com0com 命令。
- 原有“虚拟串口”菜单、驱动安装说明和系统 COM 刷新逻辑从界面和代码中移除。

## 测试范围

- 通道名相同的主站/从站实例可以建立连接并完成一问一答。
- 通道名不同的实例不能互相连接。
- 无效名称、端口占用、重复创建和对端关闭均能显示错误且可恢复。
- RTU 读线圈、读寄存器、写操作、轮询、趋势曲线和日志在内部通道上行为与真实串口一致。
- RTU、ASCII、TCP 和内部虚拟通道之间切换时，串口字段不会残留遮挡，程序可正常构建和启动。

## 非目标

- 不提供系统级 `COMx` 端口。
- 不兼容未集成内部通道协议的第三方串口软件。
- 不实现内核驱动、驱动安装包或驱动签名。
